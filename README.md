## 一、这是什么

面向健身初学者的方案生成产品：4 步问卷 → 训练体系选择 → 周计划 + 营养 + 恢复 → 打卡执行 → **AI 教练解读**。

| 层 | 内容 | 是否用 AI |
|---|---|---|
| 处方层 | `getSystem` / `getDayExercises` / `NutritionGen` | ❌ **坚持规则**——循证硬约束，须确定性可审计 |
| 解释层 | `ai-coach.js`：把打卡 + 方案变成可校验的自然语言反馈 | ✅ **最小可信 AI**——结构化输出 + 白名单校验 + 三级降级 |

**核心产品判断**：AI 放在解释层，不放在处方层；明确不做摄像头动作纠正（竞品 2026 实测误判即伤害）。

---

## 二、面试时最该讲的 5 件事

1. **为什么这里该用 AI**：输入是打卡历史+方案的组合，规则只能报数字，AI 能归因成自然语言。
2. **为什么别处不用 AI**：训练容量、动作白名单、热量公式——LLM 会漂移，规则才安全。
3. **幻觉与信任**：结构化 JSON → 动作名白名单 → 医疗词拦截 → 来源可见 → 用户可纠正。
4. **评测**：golden set 六类 + 对抗变形；越权 4/4、PII 4/4、幻觉 3/3、数字编造 4/4 全拦，误伤 0；本地解读亚毫秒级。
5. **失败与迭代**：审计时误判"能力分越高越弱"，核实一手问卷后更正规格（实现未动）。

> 完整答案索引在 `INTERVIEW.md` §9。

# 2. 看规则引擎的确定性测试

**全量回归**：

```bash
for t in test_*.js; do node "$t" || break; done   # 18 套全绿
```

无 npm 依赖、无构建、无 API Key。纯静态站，任何环境都能跑。

## 四、项目结构（面试速查）

| 文件 | 职责 |
|---|---|
| `INTERVIEW.md` | **面试叙事主文档**（先看这个） |
| `ai-coach.js` | AI 解释层：上下文脱敏 / prompt / 校验 / 降级 / 置信度 / 评测候选 |
| `ai-runtime.js` | AI 控制面：kill switch / 灰度 / 应急本地 / 宿主云通道注入 / 变体轮转 |
| `ai-grounding.js` | 事实核验：数字 groundedness（完成率/组数/训练日句式锚定，防编造） |
| `ai-templates.js` | 3 个确定性解读变体（同一批事实、换角度组织，可复现的多样性） |
| `ai-feedback.js` | 反馈可追溯：解读指纹 + 去抖 + eval 候选导出（数据飞轮闭环） |
| `test_ai_coach.js` | golden set：六类 + 对抗变形 + groundedness + 换角度；断言数以 `node test_ai_coach.js` 输出为准 |
| `data.js` | 知识库：5 体系 / 49 动作 / 循证文献库 |
| `app.js` | 引擎与编排（1400+ 行，新功能一律独立模块） |
| `specs/` | 每批功能的规格三件套（requirements / plan / validation） |
| `DECISIONS.md` | 决策与推翻记录（含 C3 铁律有限推翻的原因） |
| `CLAUDE.md` / `HANDOFF.md` | 工程地图与交接状态 |
